# 今天题材·接口自渲染方案调研报告

调研日期：2026-11-17
背景：今天题材卡片 iframe 内嵌同花顺详情页，个股列表持续加载失败。根因为上游实时行情走 `dataq.10jqka.com.cn`，`hexin-v` 反爬 token 将**顶层页面 URL** 织入指纹校验，顶层非同花顺域名一律 401，无法绕过。王总指示调研「弃 iframe，直接请求上游接口 + 自渲染页面结构」的可行性。

**结论：可行，且成本低。详情页全部业务数据其实都走 news 同源的开放接口（GET/POST 免鉴权，仅需正常 UA），iframe 里唯一 401 的 dataq 调用只服务于「板块分时图」与个股「最新价/流通市值」两处——前者可裁剪或后接自有源，后者用应用现有行情通道（腾讯 qt.gtimg.cn 批量报价）即可补齐。**

---

## 一、上游接口清单（CDP 真实抓包 + curl 逐一实测）

详情页（`news.10jqka.com.cn/app/hot_concept/v2/detail`）实际发出的请求共四类业务接口 + 一个埋点 + 一个行情聚合：

| # | 接口 | 方法 | 实测 | 作用 |
|---|------|------|------|------|
| 1 | `/app/concept_v2_api/open/api/concept/event/jtcsm/v1/event/detail?eventId={id}` | GET | ✅ 200 | 题材解读：标题/摘要（逐条）/原文链接/关联题材列表/投资方向 |
| 2 | `/app/concept_v2_api/open/api/concept/event/jtcsm/v1/theme/table?eventId={id}` | GET | ✅ 200 | **影响板块 + 成分股**：题材（含细分 children）+ risePercent + limitUpCount + topStocks（代码/名称/涨幅/涨停状态/原因） |
| 3 | `/app/concept_v2_api/open/api/concept/event/jtcsm/v1/event/quote` | POST `{"eventIds":[...]}` | ✅ 200 | 事件级行情：平均涨幅 risePercent + 涨停家数 limitUpCount（页面约 4s 轮询一次，接应用轮询设置即可） |
| 4 | `/app/concept_v2_api/open/api/concept/event/jtcsm/v1/theme/quote/increase` | POST `[{"id","type"}]` | ✅ 200 | 各题材板块实时涨幅（影响板块行的刷新） |
| 5 | `quota-h.10jqka.com.cn/fuyao/.../trade_time` | POST | ✅ 200 | 交易时间判断（是否轮询），可复用应用市场状态 |
| 6 | `dataq.10jqka.com.cn/fetch-data-server/fetch/v1/specific_data` | POST | ❌ 401 | 板块分时图 + 个股最新价/流通市值（hexin-v 反嵌，不可用） |

鉴权口径：裸请求（无任何头）会被 Nginx 拦（`Nginx forbidden`）；**带普通浏览器 UA 即 200**，Referer 非必需。与现有 `fetchHotConceptDays` 清单接口同一域名同一白名单，proxyFetch 链路零改造。

## 二、数据完整性对照（按页面结构逐块核对）

| 页面区块 | 数据来源 | 可自渲染 |
|----------|----------|----------|
| 卡片头（热度/标题/题材标签） | 已有清单接口 eventList | ✅ 已实现 |
| 题材解读（①②③ 逐条摘要 + 原文「详情」链接） | event/detail → summaryItems / jumpUrl | ✅ |
| 事件头（平均涨幅 +5.04% / 涨停 13 家） | event/quote（轮询） | ✅ |
| 影响板块（板块名 + 涨幅 + 板块分时入口） | theme/table + theme/quote/increase | ✅（分时图除外） |
| 成分股表格（名称代码/最新/涨幅/流通市值 + 涨停标记） | theme/table → topStocks（代码/名称/涨幅/涨停态）；**最新价/流通市值 → 应用现有 `fetchConstituentQuotesBatch`（腾讯 qt.gtimg.cn 批量报价，60 只/批，需扩展流通市值字段——腾讯报文字段含市值，东财 ulist 备通道 f21 同样含）** | ✅ |
| 个股点击跳详情 | 应用内已有 StockDetailView 路由，比 iframe 内跳转体验更好 | ✅ |
| 板块分时图 | 仅 dataq（401） | ⛔ v1 裁剪；后续可评估接自有分时源（概念指数 88xxxx 在腾讯/东财无对应代码，需另找同花顺指数分时开放通道） |
| 批量加自选 / 多股同列 | 应用自有自选模块可实现（可选项） | ✅（可选） |
| 更多事件 / 投票 / VIP 彩蛋 | recommend 接口未深验 / 上游 App 专属 | ⛔ v1 裁剪 |

## 三、实施方案（v1）

**架构**：`HotConceptBoard.vue` 去掉 body 级常驻 iframe 图层，卡片内自渲染详情内容（保留现有卡片横滚 + 常驻图层方案中可复用的状态机骨架，删除帧注册表/URL 堆栈/上一页下一页逻辑）。

1. **API 层**（`hot-concept.api.ts` 扩展，同域名同白名单）：
   - `fetchHotConceptEventDetail(eventId)` — GET event/detail
   - `fetchHotConceptThemeTable(eventId)` — GET theme/table（含 topStocks）
   - `fetchHotConceptEventQuotes(eventIds)` — POST event/quote（接 usePolling / QUOTES_INTRADAY）
   - `fetchHotConceptThemeIncrease(themes)` — POST theme/quote/increase
2. **行情补列**：`board-constituent-quote.api.ts` 的腾讯通道扩展流通市值字段（约 field 44/45，GBK 解码已有），成分股批量询价 + 30s 会话缓存复用。
3. **UI**（`HotConceptDetailPanel` 新组件，样式对齐上游结构）：
   - 头部：题材名 + 平均涨幅（红涨绿跌）+ 涨停家数
   - 题材解读：summaryItems 逐条 + 「详情」外链
   - 影响板块：横向标签组（板块名 + 实时涨幅）
   - 成分股表格：名称代码 / 最新（自有行情）/ 涨幅（上游值或自有值取一）/ 流通市值（自有行情）；涨停标红
   - 行点击 → 跳应用内个股详情；「批量加自选」按钮接应用自选组（可选项，v1 可后置）
4. **轮询**：usePolling(tradingAware) 驱动 event/quote + theme/quote/increase + 自有行情批量询价，间隔跟随设置页 QUOTES_INTRADAY。
5. **清理**：删除 iframe 帧注册表 / URL 堆栈 / 上一页下一页 / HOT_CONCEPT_DARK_FILTER 及白皮书相应描述。

## 四、风险与边界

- **非官方接口**：jtcsm open api 与清单接口同源同性质（免鉴权、UA 放行），上游变更风险与现状一致；本次逆向已固化四接口的完整参数/响应结构，变更容易适配。
- **数据口径**：topStocks 涨幅为上游快照，自有行情通道为准播口径时两列可能有毫秒级差异——统一以自有行情通道渲染「最新/涨幅/市值」三列更干净，上游值仅作首帧占位。
- **分时图缺失**：v1 无板块分时；若王总要，可后续专项调研同花顺指数分时的可用通道。
- **VIP 过滤**：上游对非 VIP 有 stockInfoList 过滤逻辑，但 theme/table 实测未过滤（本次返回全部成分股），风险低。

## 五、成本与收益

- 收益：彻底消除 iframe 401 / 闪刷 / 二级页返回三大问题（前两个由架构根除，第三个因「无二级页」而消失）；主题/配色/滚动自然跟随应用；个股点击进应用内详情页。
- 成本：API 层 4 个函数 + 行情通道扩展 1 字段 + 1 个渲染组件 + 清理 iframe 层，规模可控。
